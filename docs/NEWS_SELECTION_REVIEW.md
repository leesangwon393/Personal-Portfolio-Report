# DB 병합 및 성향별 뉴스 검색 점검

## 결론

DB 병합과 성향 전달·검색·리포트 연결은 동작한다. 실제 뉴스에서 성향별 차이도 있지만,
현재 결과만으로 개인화 품질이 충분하다고 판정할 수는 없다. 101개 종목 중 56개는
SAFE와 AGGRESSIVE가 같은 기사 집합을 선택했고, 원본의 종목 연결과 요약 품질 문제도 확인했다.

## DB 병합

- 원본: `db/news.db`, 작업 DB: `local_data/news/db/news.db`.
- 원본 기사·요약 1,113건이 이미 작업 DB에 모두 있어서 추가 기사 0건, 기존 일치 기사 1,113건.
- 최종 기사 1,113건, 기사-종목 연결 1,113건, 새 임베딩 1,113건, 기존 벡터 1,113건.
- 원본 기사·요약·기존 벡터를 보존했다. 원본 파일의 SHA-256도 변하지 않았다.
- 준비 스크립트를 수정해 작업 DB가 있어도 원본의 신규 기사를 ID로 병합한다.
  기존 작업 기사 보존, 반복 실행 중복 방지, 같은 ID의 내용 충돌 시 원본/작업 파일 보존을 테스트했다.
- 원본 내부의 서로 다른 ID를 하나로 합치지는 않는다. 검색 단계에서 내용·URL·이벤트 중복을 처리한다.

## 실제 MiniLM 모델로 101개 종목 점검

2025-10-31~2025-11-13에 저장된 기사·요약과 준비된 384차원 임베딩을 사용했다.
외부 시세·뉴스 API나 LLM 평가 API를 호출하지 않았다.

| 항목 | 결과 |
|---|---:|
| 종목 × 성향 | 101 × 3 = 303회 |
| 기사 3건을 반환한 검색 | 303/303 |
| 빈 검색 결과 | 0 |
| SAFE/AGGRESSIVE 기사 집합이 다른 종목 | 45/101 |
| SAFE/AGGRESSIVE 기사 집합이 같은 종목 | 56/101 |
| 선택 슬롯 중 공통 쿼리가 최고점인 경우 | 403/909 |
| 종목 혼입 방지 규칙으로 제외된 종목-기사 쌍 | 23 |

위 수치는 정확도나 Precision@3가 아니다. 기사 집합의 차이는 개인화 동작의 진단값일 뿐,
같은 기사라도 두 성향 모두에 적절할 수 있다. `best_query`와 쿼리별 유사도는 순위 이유를
추적하기 위한 값이며, `matched_queries`에 나타났다고 해당 주제에 적합하다는 뜻은 아니다.

## 내용 점검 사례

저장된 제목·요약을 읽고 확인한 사례이며, 원문과 사실관계를 대조한 전문 평가가 아니다.

| 종목 | SAFE | AGGRESSIVE | 판단 |
|---|---|---|---|
| NVDA | AI 랠리 우려·실적 발표, 고객의 GPU 구매, 공매도/가치평가 기사 | 매출 성장·제품 주기, 고객의 GPU 구매, 실적 발표 | 위험과 성장의 강조점 차이를 확인. 일부 공통 기사도 타당 |
| MSFT | 하락 후 가치평가, 클라우드 위험, 분기 실적 | 클라우드 성장 전망, 가치평가, Windows AI 기능에 대한 사용자 반발 | 관련 기업 기사는 정리됐지만 제품 반발 기사가 성장 촉매 쿼리에 매칭됨. 긍정적 성장 근거로 해석하면 안 됨 |
| AAPL | 가치평가, 실적 상회, 빅테크 실적 | 같은 3개 기사 | 기업 공통 실적 정보는 유효할 수 있으나, 이 사례의 성향별 구분은 약함 |

### 발견한 문제와 수정

1. **다른 종목 기사 혼입:** MSFT 후보에 Rapid7(RPD) 기사 및 Palantir 단독 실적 기사가 있었다.
   저장된 종목 태그만 믿었던 것이 원인이다. 제목이 다른 종목/등록 회사명을 명시하면서
   제목·요약 어디에도 요청 종목/회사명이 없는 경우 제외하도록 보완했다.
   관계기업 기사에서 요청 회사가 실제로 언급되면 유지한다.
   이는 MSFT/AAPL/NVDA/AMZN/GOOG/GOOGL/META/TSLA/PLTR 9개 종목의 명시적 별칭에 한정한
   보수적 방어이며, 모든 종목의 회사 식별 문제를 해결한 것은 아니다. 원본 DB에서 삭제하지 않는다.
2. **공통 쿼리 우세:** 현재 최고 유사도 방식은 공통 실적 기사가 여러 성향에서 반복될 수 있다.
   다르게 보이게 만들기 위해 관련성이 떨어지는 기사를 강제로 넣지는 않았다.
3. **요약 품질:** 저장된 일부 요약이 숫자·문장 중간에서 끝나고,
   의견이 포함된 기사에서 “의견 없음”이라고 서술한 경우도 있었다.
   기존 요약을 보존했고, 사실 정확도가 검증된 데이터라고 주장하지 않는다.
4. **데이터 시점:** 전부 2025년 스냅샷이므로 현재 뉴스 추천 성능으로 해석할 수 없다.
   평가 시점에서 오래된 기사들이므로 최신성 점수의 기여도 매우 작다. 최신 뉴스와 오래된 뉴스가
   함께 있는 운영 상황에서 최신성 가중치가 적절한지는 이번 실험으로 확인하지 못했다.

## 확인 범위와 다음 품질 기준

자동 테스트 58개와 실제 DB/API 연결 검증은 통과했다. 이번 결과로 확인한 것은 병합의 안전성,
검색 흐름, 일부 성향 차이와 명백한 종목 혼입의 수정이다. 성향별 “좋은 기사”의 독립 정답을
마련한 실험은 아니므로 개인화의 우수성은 미입증이다.

후속 품질 평가는 별도 종목·기간의 기사에 회사 관련성, 성향 관련성, 중요도 정답을 부여하고,
최신순 및 공통 검색 기준선과 Precision@3/nDCG@3를 비교해야 한다. 쿼리를 설계할 때 사용한
기사로만 평가하면 과적합을 놓칠 수 있다.
